# Native support adapter format

This is the **new prepared-support interface**, awaiting integration with and validation against the original native HiLiftAeroML evaluator. It is not a claim that authoritative native support has been exported. See [release status](RELEASE_STATUS.md).

## Support files

Support has a root `index.json` and `cases/<case_id>/case.json`. The index uses `hlpw6-native-support-index-v1`, a `demonstration` boolean, and `cases: {case_id: {sha256: <case.json digest>}}`. A validated production release additionally pins the index hash inside the versioned evaluator contract.

Each case uses schema `hlpw6-native-case-support-v1` with:

- `case_id` and `reference`: `q_inf`, `q_ref`, `u_inf`, `area_ref`, `chord_ref`, `aoa_degrees`, and three-component `moment_reference`. Units must match the audited native reference recipe, including coordinates in inches and the correct dimensional field scales.
- `surface`: `raw_point_ids`, nondimensional `pressure`, nondimensional `wall_shear`, float32 `weights`, physical `points`, polygon `connectivity` and `offsets`. Raw IDs are sorted, contiguous, zero-based and cover the entire boundary; connectivity indexes this exact point order. Polygon offsets include the initial zero and final connectivity length.
- Optional `volume` for full-scope support: sorted valid raw `raw_point_ids`, nondimensional `pressure`, nondimensional vector `velocity`. These arrays exclude the frozen zero-pressure rows without renumbering original IDs.
- Optional `region_ids` per submitted domain: uint8 codes 0–3 from the frozen normalized-coordinate definitions in `contract/regional-diagnostics.json`. If regions are supplied, include all submitted fields and all cases.
- `profiles`: `{path, sha256}` for the authoritative compact support NPZ accepted by the retained reference implementation. This is float64 scoring support with physical graph/arc-length/line weights, not the dashboard's display copy.
- `cp_stencil` and (for full scope) `velocity_stencil`: CSR-like `raw_point_ids`, `weights`, `offsets` mapping complete native point fields to exactly the retained Cp nodes or valid velocity station rows. Preserve native branch ordering and interpolation; do not create stencils by nearest-neighbour substitution. Velocity stencils interpolate the vector before its magnitude is taken.

Every array descriptor is `{path, sha256, dtype, shape}`. Paths are relative to `case.json`'s directory; arrays are NPY files read with `allow_pickle=False`. Production files should be little-endian and use the exact published precision. Support values and predictions must use the same nondimensional basis. All descriptors and references require source audit before release activation.

## Prediction files

Predictions use `entry/cases/<case_id>/<domain>/manifest.json`, schema `hlpw6-native-predictions-v1`, `domain`, `basis: hiliftaeroml_nondimensional`, and a non-empty `chunks` list. Each chunk holds descriptors for int64 `raw_point_ids`, scalar `pressure` and vector `wall_shear` or `velocity`. The `PredictionWriter` creates this layout. The evaluator validates checksums and complete coverage, then reduces in canonical order using bounded chunks and scratch memory maps.

## Synthetic example

The tiny synthetic example generated by `hlpw6-aiml demo` is useful for studying the file layout. Its geometry, truth, interpolation and weights are artificial and do not establish native scientific equivalence.
